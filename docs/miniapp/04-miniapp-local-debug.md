# 微信小程序：本地开发与调试

小程序正式运行需要已备案的域名和 https 证书，开发阶段不方便每次部署，因此这一节说明如何用本机地址先把功能跑通。

## 本地准备

| 项目 | 说明 |
| --- | --- |
| 后端 | 本机启动 MossKB 服务，默认端口 `10060` |
| 小程序工程 | `mosskb-miniapp`，用微信开发者工具导入构建产物 |
| 微信开发者工具 | 打开「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」 |
| 数据库 | 与后端使用同一套库，智能提示与知识库数据都来自这里 |

## 本地直登

小程序正常登录需要用小程序的 appid 与 secret 换取用户标识。本地联调往往还没有配置这两项，因此提供了本地直登：

1. 在配置中打开 `wechat.miniapp.dev-login=true`。
2. 小程序请求登录接口时只带 scene，不带微信登录凭证。
3. 服务端按 scene 找到智能提示，直接登记访客并签发令牌。

需要注意：

- 源码目录直接启动时该开关默认放行；打包后的运行环境必须显式打开才生效，正式环境请保持关闭。
- 直登只是跳过「验证微信用户身份」这一步，公开访问的启停与次数限制照常生效。
- 开启后日志里会打印一条提醒，提示发布前配置小程序凭据。

## 请求地址

| 调试方式 | 请求地址 | 说明 |
| --- | --- | --- |
| 微信开发者工具模拟器 | `http://localhost:10060` | 与后端同机，可直接访问 |
| 真机调试 | `http://局域网IP:10060` | 手机与电脑需在同一网络，且服务需监听可被外部访问的地址 |
| 真机 + 内网穿透 | 穿透工具给出的 https 地址 | 需要 https，适合验证接近正式环境的行为 |

小程序工程的请求地址通过构建配置注入，默认是 `http://localhost:10060`；切换环境只需要改配置，不需要改代码。

## 小程序码在本地怎么扫

微信官方接口生成的小程序码指向的是已发布的小程序页面，本地开发无法直接扫码。开发阶段的做法：

1. 把小程序码的运行环境设置为 `develop`，并关闭页面校验。
2. 用微信开发者工具打开工程，手动在页面参数里填写 scene 调试。
3. 需要验证真实扫码时，用微信开发者工具的「预览」生成开发版二维码，在手机上打开后由页面自行读取 scene。

scene 的内容就是智能提示的公开访问令牌，可以在管理端的小程序码页面复制，也可以在数据库的公开访问记录里查到。

## 自检清单

| 检查项 | 期望结果 |
| --- | --- |
| 携带有效 scene 登录 | 返回令牌与智能提示标识 |
| 携带无效 scene 登录 | 返回「小程序码无效，或该智能提示已停止对外访问」 |
| 不带 scene 登录 | 返回「缺少 scene，请从小程序码进入」 |
| 用访客令牌取资料 | 返回名称、简介与开场白 |
| 用访客令牌建会话 | 返回会话标识 |
| 用其他访客的会话标识提问 | 返回「无权访问该会话」 |
| 关闭公开访问后再登录 | 返回小程序码无效，无法进入 |
| 未配置微信凭据且未开直登 | 返回服务端未配置微信小程序凭据 |

## 服务端自检

仓库内有一个针对小程序链路的联调测试，会连真实数据库验证 scene 解析、访客令牌、会话创建与权限校验：

```bash
mvn -pl mosskb-web -am test -Dtest=MiniAppApiTest -DfailIfNoTests=false
```

测试不会调用外部推理服务，提问部分只验证到参数与权限校验，因此可以在没有模型密钥的环境里运行。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 小程序请求失败，提示不在合法域名列表 | 开发者工具里打开「不校验合法域名」 |
| 真机访问 localhost 失败 | 手机上的 localhost 指手机自己，改用局域网 IP |
| 登录返回缺少 scene | 小程序不是从小程序码进入，或页面没有解析到 scene 参数 |
| 提问一直转圈直到超时 | 模型服务较慢，可调大等待上限，或检查模型密钥是否可用 |
| 回答为空 | 查看服务日志中的推理服务错误，模型密钥或额度问题最常见 |
| 扫码后打开的是首页而不是对话 | 小程序码的页面路径与工程页面不一致，重新生成并确认 `page` |
